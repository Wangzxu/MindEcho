# MindEcho 大模型服务与选型技术规约书

在校园 AI 心理委员系统中，我们设计了 **三类模型分工协同** 的架构方案，以在满足“高共情、双驱动”的业务要求的同时，在大模型即时生成时延与深度推理分析之间取得平衡。

本文件对系统所需的大模型、对应的核心功能、参数设置及硅基流动平台模型选型推荐进行系统归纳。

---

## 1. 向量嵌入模型 (Embedding Model)

### 📌 核心功能与应用场景
1.  **RAG 科普知识库检索**：
    *   将上传的心理学文档切片（Chunk）进行向量特征计算，同步存入 ChromaDB `psychology_kb` 集合。
    *   在学生咨询心理学概念时，将改写后的查询词实时转化为向量，在库中进行高维空间距离检索。
2.  **安全预警语义兜底（Level 3 路由）**：
    *   将用户输入向量化，与 `safety_warnings_kb` 高危样本比对，相似度 > 0.85 时熔断为 CRISIS。
    *   与 LLM 三分类（Level 2）**并行执行**，不增加路由时延。

### 🤖 模型选型推荐 (硅基流动平台)
*   **推荐型号**：`BAAI/bge-large-zh-v1.5`
*   **备选型号**：`BAAI/bge-m3`
*   **选型理由**：对中文心理学专有名词和口语化表达表征精准，维度达 1024 维，检索粒度细腻，推理速度极快（平均 $< 30\text{ms}$）。

## 2. 轻量级意图分类模型 (Simple/Lightweight LLM)

### 📌 核心功能与应用场景
1.  **语义意图分类路由（Level 2）**：
    *   对通过敏感词过滤后的学生输入，调用轻量模型进行极速语义三分类。
    *   输出符合严格 Schema 的 JSON，分类结果：`CRISIS`（危机）、`KNOWLEDGE`（科普）、`EMOTION`（共情对话）。
2.  **用户查询词重写 (Query Rewriting)**：
    *   将学生输入的口语化长文本，在 RAG 检索前提炼为 1-2 个心理学科普关键词（如"焦虑引起的失眠 调节小技巧"），降低搜索噪声。
3.  **知识卡片提炼 (Knowledge Card Refining)**：
    *   将 RAG 召回的父文档全文提炼为结构化科普卡片 `{concept 概念释义, tip 调节技巧}`。
4.  **记忆合并提取 (Memory Bundle)**：
    *   一次调用同时输出【用户画像增量 + 滚动摘要】，替代原先两条独立管线（画像提取 + 摘要压缩）。

### ⚙️ 参数调优规范
*   **意图分类**：`Temperature = 0.0`，`Max Tokens = 30 ~ 50`，确保分类确定性。
*   **查询重写**：`Temperature = 0.0`，`Max Tokens = 30`。
*   **卡片提炼**：`Temperature = 0.3`，`Max Tokens = 200`。

### 🤖 模型选型推荐 (硅基流动平台)
*   **推荐型号**：`Qwen/Qwen2.5-7B-Instruct`
*   **备选型号**：`GLM-4-9B-Chat`
*   **选型理由**：指令遵循能力强，可稳定输出指定格式的 JSON 数据，时延低、吞吐高。

## 3. 高共情对话大模型 (Complex/High-Capability LLM)

### 📌 核心功能与应用场景
1.  **多轮心理共情陪伴（`EMOTION` 路由）**：
    *   扮演温柔、包容、非批判性的心理委员角色。
    *   采用"同理心共情 ➔ 情绪抱持 ➔ 启发引导觉察"三步法舒缓学生情绪。
    *   必须支持 **Server-Sent Events (SSE) 流式返回**，保障首字渲染（TTFT）时间在 2 秒以内。
2.  **知识科普温和解答（`KNOWLEDGE` 路由）**：
    *   将 RAG 检索提炼出的专业心理卡片（概念释义 + 自助技巧）作为背景知识注入，进行人性化、无说教感的深度润色解答。

### ⚙️ 参数调优规范（意图定制温度）
| 意图 | 温度 | 理由 |
| :--- | :--- | :--- |
| `KNOWLEDGE`（科普） | `0.3` | 重科学准确，低随机性 |
| `EMOTION`（倾诉） | `0.8` | 重共情自然，高随机性 |
| 其他（默认） | `0.7` | 平衡 |

*   **最大 Token 限制（Max Tokens）**：`1024`，保障完整话语的顺畅生成。

### 🤖 模型选型推荐 (硅基流动平台)
*   **推荐型号**：`deepseek-ai/DeepSeek-V3`
*   **备选型号**：`Qwen/Qwen2.5-72B-Instruct`
*   **选型理由**：作为大体量模型，能精准把控人类细微的情感变化，抹除大模型惯有的"直男说教腔"，生成流式回复速度极快。

### 🛡️ 失败降级链
复杂模型流式失败时依次降级：
1. Qwen 简单模型非流式兜底（同意图温度）；
2. 固定安抚话术（"听到你说了这么多…我一直在这里陪着你。"）。
保证用户始终得到回复，不向 SSE 抛错。

## 4. 会话记忆与上下文压缩策略规范

### 🧠 1. 四层记忆架构

| 层 | 内容 | 存储 | 生命周期 |
| :--- | :--- | :--- | :--- |
| RAG 召回 | 科普知识卡片 | ChromaDB | 持久 |
| 窗口层 | 最近 12 条原始对话 | state / MySQL | 最近 12 条 |
| 中期记忆 | 窗口外的滚动摘要（≤150字） | 内存 `midterm_summaries_map` | 进程内（不落库） |
| 长期画像 | 压力源/技巧/关系网 | MySQL `user_profiles` | 持久 |

### 💾 2. 记忆维护触发机制（滑窗 + 合并）

```
save_message_node
  ├─ 画像触发: 消息数 ≥ 20 且 自上次增量 ≥ 10（滑窗，不依赖恰好倍数）
  └─ 摘要触发: 窗口 > 20 条（裁剪回 12 条）
      ▼
  update_memory_background（一次 LLM 调用 extract_memory_bundle）
      ├─ 画像增量 → MySQL user_profiles
      └─ 滚动摘要 → 内存中期记忆
```

- **合并提取**：画像 + 摘要一次 LLM 调用输出，替代原两条独立管线，减少重复分析与 API 调用；
- **中期记忆不落库**：服务重启即清空，应对高强度连续聊天的上下文丢失（窗口外的历史由摘要承载）；
- **窗口层启动加载**：每次启动/恢复时从 MySQL 加载最近 12 条对话。

### 🧠 3. 双会话产品形态
每个用户注册时固定创建两个会话（名称固定，不做自动命名）：
- 💬 **直接聊天**：常规会话，消息落库，四层记忆全量生效；
- 🔒 **无痕树洞**：无痕会话，消息不落库（仅内存），阅后即焚。

## 5. 业务链路与大模型分工总览表

| 触发业务 | 执行时序 | 模型类型 | 推荐选型 | 运行温度 | 输出格式 | 核心职责 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **敏感词/意图路由** | 同步实时 | 快速模型 | `Qwen2.5-7B-Instruct` | `0.0` | `JSON Object` | Level 1 敏感词 + Level 2 意图三分类 |
| **预警语义兜底** | 同步实时（与分类并行） | 向量模型 | `bge-large-zh-v1.5` | - | 1024维特征 | Level 3 危机向量匹配 |
| **查询词提炼重写** | 同步实时 | 快速模型 | `Qwen2.5-7B-Instruct` | `0.0` | 纯文本词汇 | 提炼核心词服务于 RAG |
| **向量特征生成** | 同步实时 | 向量模型 | `bge-large-zh-v1.5` | - | 1024维特征 | 向量化改写词或知识库 Chunk |
| **知识卡片提炼** | 同步实时 | 快速模型 | `Qwen2.5-7B-Instruct` | `0.3` | `JSON Object` | 父文档 → concept/tip |
| **科普润色解答** | 同步实时 | 高共情模型 | `DeepSeek-V3` | `0.3` | `SSE Stream` | 融合知识库温和解答 |
| **日常倾诉共情** | 同步实时 | 高共情模型 | `DeepSeek-V3` | `0.8` | `SSE Stream` | 共情流式陪伴 |
| **画像+摘要合并提取** | 异步后台 | 快速模型 | `Qwen2.5-7B-Instruct` | `0.3` | `JSON Object` | 画像增量 + 滚动摘要一次输出 |
